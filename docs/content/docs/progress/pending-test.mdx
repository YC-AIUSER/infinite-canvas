# 待测试

- 画布批量上传素材（2026-07-27 修复用户实测问题，含对抗审查补齐）：文件选择器开放多选（替换已有节点内容的入口仍为单选），空白处上传与拖拽改为循环处理全部文件，每个文件一个节点、按 48px 斜向级联摆放；批量按文件顺序依次创建（保证节点顺序与遮挡层级可预期），单文件仍保持原「选中+打开面板」行为，批量不弹面板也不动现有选中；混入不支持的文件会提示「已忽略 N 个」，单个文件上传失败提示文件名且不影响其余文件；替换目标在读取后立即清理，降低连续替换两个节点时的串台概率。**需实测**：选择器多选、一次拖 5+ 个混合图/视频/音频、拖入含 PDF 的混合文件看忽略提示、替换节点内容仍是单选。**已知缺口**：同一节点连续两次替换且前一次上传较慢时，旧文件仍可能后到覆盖（旧有隐患，未加请求序号校验）；批量部分失败只有逐条 toast，无汇总提示。
- Toonflow 创意的剧本依赖进版本守卫（2026-07-27，对抗审查补齐）：创意读剧本是隐式依赖（剧本在创意下游，连线方向表达不了，反向加边会与既有连线成环），现改为把实际读取的剧本版本记进创意产物的 upstreamVersions，失效传播时反查这份记录——谁记着我的旧版本谁就过期。**需实测**：生成创意 → 重新生成剧本 → 创意应变为「已失效」；创意基于剧本当前版本时不应被误标失效。
- 画布 Agent 正文同步进产物（2026-07-27，对抗审查补齐）：Agent 改写已有文本产物的环节正文时，新正文会同步写进产物并升版本，下游按版本守卫失效。正文没变时不升版本；分镜表/锁定表/继承表等结构化产物不参与同步（避免用散文替换表格）。**需实测**：让 Agent 改写剧本正文，确认节点显示新正文、下游变为「已失效」、版本号+1；重复发同样内容不应反复升版本。
- 本地 Agent 选区路径的词库（2026-07-27，对抗审查补齐）：`canvas_get_selection` 在 Agent 侧用缓存本地计算、网页不参与，此前拿不到词库。现由网页在推送画布状态时带上词库、Agent 缓存后在选区结果里附上。**canvas-agent 已重新构建，需重启本地 Agent 的 MCP 进程才生效**。**需实测**：Agent 只调选区（不调画布状态）时也能拿到词库。

- Toonflow 创意读剧本（2026-07-27 修复用户实测 bug）：模板连线是 项目→创意→剧本 的单链，生成时只取上游，创意因此永远读不到剧本，`buildCreativePrompt` 必然判定为无剧本、走冷启动碰撞法另编一个故事（实测创意产出首行自陈"输入上下文仅有【project】…没有已有剧本或分集大纲"）。现改为从全画布直取**真正写过内容**的剧本节点：有产物的优先，其次是正文被写过的，模板占位文案与空节点不注入（避免体检一份不存在的剧本）。已用模板画布与"多个 script 节点"两个用例覆盖。**需真实模型实测**：有剧本时创意确实进入体检模式并对着真剧本挑缺口；画布上存在多份剧本（段实例/用户复制）时选中的是不是预期那一份。**已知缺口**：创意对剧本的依赖没有进入版本守卫，剧本更新到新版本不会把创意标记为失效，需人工留意。
- Toonflow 节点正文显示与自动撑高（2026-07-27 修复用户实测 bug）：剧本/创意/空间合同/镜头合同/动作合同等纯文本环节的产出此前在节点上没有渲染分支，生成完正文原地消失、只剩校验项清单；Agent 通过画布工具写进 `metadata.content` 的正文同样不显示（实测节点已被写入 385 字而界面纹丝不动）。现改为产物优先、无产物时兜底显示节点正文，模板占位文案仍不占正文区（判据只比对摘要那一半，因为标题会被 Agent 改写）。同时生成完成后按内容量撑高节点（真实排版参数 12px 字号 / 20px 行高，上限 520，用户手动调大过的不缩小）。**需实测**：撑高后与下一排节点的重叠程度是否可接受（点「一键整理」可排开）、超长产出滚动是否顺畅、结构化环节（分镜表/锁定表/继承表）保持表格视图不受影响。**已知缺口**：节点已有产物时，Agent 改写正文仍会被产物遮住、界面看不到变化。
- 画布 Agent 元数据净化（2026-07-27）：Agent 写节点时会拦截七态之外的非法状态（实测收到过 `ready`，会让状态徽章渲染成空白）、把只传部分字段的更新补回原有环节字段、并阻止残缺字段把普通文本节点污染成环节节点；新建节点与更新节点两条路径都覆盖。旧数据里已有的非法状态在画布加载时会自愈为「未开始」。**需实测**：让 Agent 改写环节状态与正文，确认徽章显示正常、环节字段不丢失。
- 本地 Agent 封闭词库注入（2026-07-27）：Agent 侧此前只有"从封闭词库逐字选取"这条命令，词库实体在网页代码里且没有任何工具能读到，Agent 因此卡在分镜决策锁定表并向用户索要词库。现在网页返回画布状态时（`canvas_get_state` / `canvas_export_snapshot`）附带全部 11 类词库全文，约 3.4k 字符，非 Toonflow 画布不附加。**需实测**：让 Agent 做分镜决策锁定表，确认它不再索要词库且选词确实落在封闭集内。**已知缺口**：`canvas_get_selection` 在本地 Agent 侧直接计算、网页不参与，走这条路径仍拿不到词库；长会话里状态结果被裁剪后也可能丢失词库。

- Toonflow P7 导演技法决策持久化：分镜表仍输出纯 JSON 数组，每段 `shotNo` 最小的首行携带 `p7`，同段其余行省略；质量检查会核对九类主目的、主辅目的行内具体技法数量与归属、剧本依据及可执行转写，旧产物不带 `p7` 时只显示「无法判定」且不阻断。需用真实模型生成含主目的、辅目的两类段落，确认首行落字段、其余行不重复，并验证面板能显示具体越界技法名。
- 画布 Agent 精简快照：`canvas_get_state`、批量操作及其他画布工具默认仅返回必要结构，长正文和 Toonflow 当前产物截断到 200 字，历史版本、洗词明细和内联 dataURL 不再进入默认结果；`canvas_get_state` 可传 `nodeIds` 按需取回指定节点的完整未截断内容。需在真实大画布连续对话中确认 rollout 增长速度与工具读取体验。
- Toonflow 高潮/爆点镜三件套：分镜表、镜头合同、动作合同提示词会把镜头身份、L5 五部位参数、Speed Ramp 四要素与 L4/L5 景别写入固定字段；高潮镜优先按 mood 的「高潮/爆点镜」前缀识别，动作关键词必须同时有高情绪值或镜头合同 Speed Ramp 才升级为候选。五部位按 `头部=…；肩背=…；手部=…；身形=…；身段=…` 逐项绑定，前四项检查可观测参数，身段只检查整体气质描述；结构缺失时显示「需人工确认」。需用真实模型生成冲突爆点、变身或冲锋段，确认三个环节都按约定字段产出，且日常赶车等动作不会误报高潮镜。
- Toonflow 节点流式回显：文本类环节（剧本/创意/镜头合同等）生成中在节点内实时逐段显示模型输出，结构化环节（分镜表/分镜决策锁定表/跨段继承表/资产库）显示小字灰底的原始流尾部并标注「完成后转为表格」，落定后自动换回正式产物渲染。生成期间节点自动撑高到 440px（模板 190px 只够挤出一行等于看不见），原高度记进 `streamRestoreHeight`，收尾/刷新时原样还原；用户自己已调得更高的节点不动尺寸。已用本地假 SSE 服务端到端实测剧本（文本模式）与分镜表（raw 模式）：文本随流增长并自动滚动到底、节点撑开后可读多行、成功与失败落定后流式区消失且高度与字段全部复原，刷新中断路径经 `hydrateToonflowProject` 清理后同样回到原高度。**仍需真实模型实测**：视频工作台 Module4 合成的流式（与剧本同一条链路但未单独跑过）、Gemini 调用格式下的流式分片是否同样逐段到达、长剧本连续流式时画布的滚动与性能表现。已知取舍：撑高期间节点可能与下方一行节点短暂重叠，生成结束即恢复。另：生成中的取消入口在 Toonflow 节点卡片上不可达（「生成中」按钮为禁用态），取消路径的清理逻辑未经 UI 验证。
